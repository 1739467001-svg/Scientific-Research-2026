## 0.5 ⭐ 白话导读

**做一个新药要走很多步**：先找"打谁"（靶点），再设计"用什么打"（分子），再把分子调到又稳又好（优化），再证明能稳定大批量生产（CMC），再写厚厚的申报材料，最后做临床试验。过去大家谈 AI 制药，几乎只谈第二步"设计分子"。

**这篇文章的主张是：每一步都有瓶颈，所以 AI 要进入每一步。** 它拿出七个例子：

| 环节 | 合作方 | Claude 做了什么 | 结果（自述） |
|---|---|---|---|
| 药物形态工程 | Generate Biomedicines | 用 Claude Code 重新设计 CAR-T 基因指令中的一段 | 新设计**缩短约 70%**；受体表达约 **10 倍**，杀瘤更有效、持续更久 |
| 苗头发现 | Divergence Labs（食物过敏） | 把目标转成设计方案，**基本自主**地在约一个月内生成约 **35,000** 个抗体设计 | 3 个能结合 IgE，20 个能把 IgE 从细胞上拆下来，其中 3 个**强于标准药** |
| 先导物优化 | BigHat Biosciences | 接入其实验数据系统 Reccy，提出突变；**质疑并改写评价指标** | 约 10 周测 1,010 个变体；亲和力 **>10 倍**，耐热高 **18°C**，聚集慢 **>100 倍** |
| 生产与申报 | Enveda | 审核 1,061 页生产文件，起草监管文件 | 人工发现的 **11 个问题全中**，另报 **7 个**人工漏掉的；审核时间降 **89%**（25 小时→<3 小时）；一份文件 **4 小时**完成（人工约 3 个月） |
| 公司创建 | The Column Group → Pleiades | 让小团队跑更多、更复杂的药物项目；第一个 Claude skill 用于评估靶点 | 在 **45 个靶点—疾病对**上做过评估（**未给结果**） |
| 临床试验规划 | Bristol Myers Squibb | 评估早期临床方案、估计试验成功概率 | 2027 年扩展；目前只有一段高管评价 |
| 自营项目 | Mithril Medicine（被 Anthropic 收购） | 一人公司，Claude 协调与 **11 家外部实验室**的合同、物流、实验 | 一种罕见儿童肌营养不良候选药 **<18 个月**从想法到小鼠有效；最快 **2028 年底**进临床 |

## 3. 逐单元深度解构

### 3.1 单元一｜论点：瓶颈是"分布式"的

**事实层**：原文明确说 "There is no single problem to solve; the bottlenecks are distributed all throughout the drug development process."

**解构层**：这是对行业主流叙事（AI 制药 = 分子生成）的**直接反驳**。本知识库之前的 AIDD 情报（005 Anew Labs、008 BindCraft2）都集中在"设计"一步；这篇把视角拉到**整条价值链**，其中两个案例（Enveda、BMS）**根本不涉及分子**，是文件和决策工作。

> 💡 **关键洞察**：对 Anthropic 来说，这个定位是自然的——通用大模型在"读写文档、协调流程"上的优势远大于在"预测结合能"上的优势。**它选择在自己最强的地方定义问题。** 读的时候要意识到这一点。

### 3.2 单元二｜BigHat：AI 修改了验证器

**事实层**：优化过程中团队怀疑标准的热稳定性与聚集指标有误导性；Claude 与研究员**重分析原始数据**，提出新指标和改动的实验方案；BigHat 科学家改进后执行，主要预测成立。

**解构层**：前面多条洞察说"验证器才是瓶颈"（9、28），但都默认验证器是人定的、固定的。这里第一次出现**智能体在闭环里质疑并修订读出方式**。这既是能力（不盲从指标），也是风险（如果 AI 能改裁判，"生成者不能给自己打分"的原则就要求**改指标这一步必须由人和独立实验确认**——原文恰好是这么做的：科学家改进方案后再跑实验）。

> 💡 **关键洞察**：这是洞察 28 的一个正面范例：AI 提出新验证器，但**验证器的验证**仍由独立的湿实验完成。

### 3.3 单元三｜Enveda：文件审核的"召回率"

**事实层**：1,061 页文件；人工发现 11 个问题，Claude 全部命中；另报 7 个人工漏掉的问题。

**解构层**：从统计角度看这是一个**以人工为金标准的召回率 = 11/11**。但 ① n=11 很小，**Wilson 95% 置信区间下限约 74%**，不能说"不会漏"；② "7 个人工漏掉的"是否都是真问题，原文没说经过谁裁定；③ 原文**没有报告误报数**（Claude 一共标了多少条？），所以**精确率未知**——而审核时间降 89% 是否包括逐条排除误报的时间，也不清楚。

> 💡 **关键洞察**：这正是医疗/文书类智能体最典型的评估设计：**以人工为参照的召回、外加需要裁定的"额外发现"、以及经常被省略的误报率**。

### 3.4 单元四｜Divergence：分母缺失

**事实层**：约 35,000 个设计 → 3 个 IgE 结合物 + 20 个拆离物（3 个强于标准药）。

**解构层**：35,000 是**计算设计数**，不是实验测试数。实际合成并测试了多少个，原文未给——**没有分母就没有命中率**，也无法与情报 008 BindCraft（10%–100%）或 CHK-001 谷歌适配体（42.1%）比较。这正是检查清单第 18 条的第三问"计算指标还是实验指标"。

### 3.5 单元五｜Mithril 与 Pleiades：AI 作为"运营层"

**事实层**：一人公司借助 Claude 协调 11 家外部实验室，<18 个月做到小鼠有效；TCG 新设 Pleiades，想用 Claude 让小团队同时跑多个项目。

**解构层**：这两个案例的价值不在科学，而在**组织形态**——把合同、物流、外包实验的管理交给智能体。它和 CHK-001 谷歌"自主实验室"走的是两条路：谷歌是**自建机器人**，Mithril 是**智能体 + 外包 CRO 网络**。后者对没有自动化平台的课题组门槛更低。

### 3.6 单元六｜BMS：临床成功概率估计

**事实层**：BMS 用 Claude 评估早期临床方案并估计成功概率；只有一段高管引语，无数据。

**解构层**：**估计临床试验成功概率（PoS）本身是一个统计学问题**——需要历史基础率、先验、方案特征的协变量，以及**概率是否校准**。原文没有任何校准或回测证据，目前只能当作"方向"，不能当作"结果"。

## 4. 批判性解读

1. **选择性报告**：七个案例全部是正面结果，没有失败项目，也没有"Claude 不行的地方"的具体例子（原文只笼统说"已据此确定模型改进优先级"）。
2. **缺对照**：Generate 的"短 70% 且更有效"、BigHat 的"10 倍"都是相对原始分子，而**不是相对"不用 Claude 的同等投入"**。没有人工对照组，就分不出是 Claude 的贡献还是常规优化本来就能做到。
3. **人机分工不透明**：Generate 是"六位科学家使用 Claude Code"，BigHat 是"科学家 + Anthropic 研究员 + Claude"——**有 Anthropic 自己的研究员深度参与**，可复制性要打折扣。
4. **利益相关**：Anthropic 收购 Mithril、与 TCG 共建公司——**作者同时是这些项目的股东或合作方**。
5. **与本知识库此前结论一致的地方**：大部分真正的"硬结果"仍来自**湿实验读出**（BigHat 1,010 个变体、Mithril 小鼠实验），再次印证洞察 11"数据而非模型"。
6. **对课题组的现实约束**：专题报告 2026-09-23 已核实**中国大陆不在 Anthropic 支持地区**。文中提到的 Claude Science、科研额度、生命科学验证计划、客座研究员征集，**课题组大概率无法直接申请**——借鉴的应是方法与评估设计，而不是工具本身。

1. **【低成本高价值】把 Enveda 的评估设计写成医疗智能体评估模板**：以人工为参照的召回率 + 置信区间；"额外发现"由第二位专家盲审裁定；**强制报告误报数与精确率**；时间节省要包含复核误报的时间。
