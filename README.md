# Scientific Research 2026｜导师情报知识库

> 一个持续积累的个人科研知识库。
> **协作方式**：本人转发李晓林教授（博士导师）发布的项目相关信息 → Claude 负责研究分析、拆解解构、形成 Markdown 报告并归档。

---

## 📌 协作流程（SOP）

```
①  本人转发导师发布的信息（公众号推文 / 论文 / 新闻 / 通知）
    ↳ 推荐：将推文转为 Word（.docx）提供——文字无识别误差，且原文配图可提取入库
        ↓
②  Claude 研究分析：这具体是什么？来源？可信度？
        ↓
③  Claude 拆解与解构：骨架分解 → 逐单元深解 → 术语解构 → 批判性解读
        ↓
④  Claude 形成 Markdown 报告 + 原文存档
        ↓
⑤  归档入库 → 提交 Git → 知识库索引更新
```

每份报告固定包含：
1. **情报元信息**（来源、时间、可信度）
2. **一句话结论**
3. **全文骨架拆解**
4. **逐单元深度解构**
5. **关键术语解构表**
6. **批判性解读**（争议点、局限、反方证据）
7. **对课题组的关联分析与可行切入点** ← 知识库的核心价值
8. **待追踪清单**

## 🔒 敏感信息处理规范（长期规则）

> ⚠️ **本仓库是公开仓库**（GitHub `private: false`）。任何人都能看到全部内容。

### 绝对不入库

| 类型 | 原因 |
|---|---|
| **未发表的论文题目、方法名、模型代号** | 🔴 抢发（scoop）风险最高 |
| **课题组内部追踪表 / 进度表原件** | 🔴 同上 + 个人绩效信息 |
| **同事姓名与其工作进度的对应关系** | 🟠 个人信息 |
| 含上述内容的**截图、xlsx、csv** | 🔴 `.gitignore` 已拦截 |

### 处理方式

内部资料 → **只提交脱敏后的聚合统计与分析结论**，放入 `02-团队分析/`，文件名标注「（脱敏版）」，并在文档开头写明：
① 为什么脱敏　② 移除了什么　③ 保留了什么　④ 原件如何处置

**每份脱敏文档提交前必须做一次泄漏检查**（grep 人名、方法名、题目片段），确认零残留。

### 可以入库

公开来源的文章解读、公开可查的人物信息、公开论文与数据集——即 `01-情报归档/` 与 `00-人物认知/` 的现有内容。

## 🏷️ 命名规范

**文件夹命名 = `发布日期` + `_` + `公众号原标题`**

```
2026-09-13_Preprints｜数亿细胞、数十亿参数之后：单细胞基础模型下一步往哪里走
└────┬────┘ └──────────────────────┬─────────────────────────────────┘
  发布日期                    公众号原标题（保持原样，不改写）
```

规则说明：
| 规则 | 说明 |
|---|---|
| 日期格式 | `YYYY-MM-DD`，取**推文发布日期**（非入库日期）；入库日期记录在报告元信息表中 |
| 标题 | **保留公众号原标题**，不做缩写或改写，便于原文回溯 |
| 分隔符 | 日期与标题之间用半角下划线 `_` |
| 标点 | 保留原标题的全角标点（`｜` `：` `、`），仅在遇到会破坏文件系统的半角字符（`/` `\` `:` `*` `?` `"` `<` `>` `|`）时替换为对应全角字符 |
| 主文件名 | 分析报告固定命名 `README.md`，使其在 GitHub 上打开文件夹即可直接阅读 |

### ⏰ 时间标注规则（三个时间，不要混淆）

每份报告的元信息区固定记录三个时间：

| 字段 | 含义 | 用途 |
|---|---|---|
| **推文发布时间** | 公众号自己的发布时间戳（已是中国时间） | 文件夹命名取它的**日期**部分 |
| **导师分享时间** | 李晓林教授转发该链接的时间，**统一记为中国时间** | 判断导师的关注节奏与阅读路径 |
| **入库时间** | 本知识库归档整理的日期 | 版本追溯 |

**⚠️ 英国时间 → 中国时间的换算（本人身处英国，截图时间为英国本地时间）**

```
英国夏令时 BST (UTC+1)  →  中国 (UTC+8)   =  +7 小时   ← 每年 3月底 ~ 10月底
英国标准时 GMT (UTC+0)  →  中国 (UTC+8)   =  +8 小时   ← 每年 10月底 ~ 次年 3月底
```

| 年份节点 | 英国时制 | 换算 |
|---|---|---|
| 2026-03-29 ~ 2026-10-25 | BST | **+7 小时** |
| 2026-10-25 起 | GMT | **+8 小时** |

> **务必注意**：约 **2026-10-25** 英国转回 GMT 后，差值从 +7 变为 **+8**。此后若仍按 +7 换算会整体偏早一小时。
> 记录格式：`2026-09-13 23:57（中国时间）／ 原始截图 16:57（英国时间）`——**两个时间都留档**，这样即使换算规则用错也能事后修正。

## 🧭 累积性洞察（跨情报提炼）

> 本节汇总从多条情报中反复出现的、超越单篇文章的判断。每次新增情报后回看更新。

1. **课题组主线 = 单细胞/多组学 AI + 生命科学大模型**，导师转发的信息大概率是该主线的**竞品扫描或路线图校准**，而非泛行业资讯。（依据：情报 001 与李教授课题组方向高度重合）
2. **"规模不等于能力"在生物领域比在 NLP 领域更成立**——有效数据量应按"生物学情境多样性"而非细胞数度量。（依据：情报 001 §3.4）
3. **当前 scFM 的真实能力边界在"排序"而非"定量"**——成功的实验验证案例几乎都是候选筛选/排序任务。（依据：情报 001 §3.6 vs §4）
4. ⭐ **情报 001 与 002 在"自我改进闭环"上严丝合缝**：001 的结尾说生物领域需要"实验室在环"闭环但"真正自主运行的闭环仍然少见"；002 正好给出这个闭环的**通用架构语言**（Loop Kernel + 三算子 + 密封验证器）。**连续两天的两篇不是两条资讯，是一条主线。**（依据：情报 001 §5 层次三 × 情报 002 §7.1）
5. **"新知识只能来自实验数据"在两篇中被独立证实**：001 说观察性图谱学不出因果、必须要扰动数据做锚点；002 的第五定律说没有任何循环能创造能力、只能重排已隐含的知识。**两个领域、两套语言，指向同一条约束。**
6. **验证器（evaluator）是把 AI 自改进引入生物医学的真正卡点**：002 定律一说循环只在**可机器验证**处闭合，而生物学恰是"由论证、复现、测量裁决"的开放领域——这既是 001 §4"扰动预测缺乏统一基准"的同一个缺口，也是课题组最值得抢占的位置。
7. ⭐⭐ **"排序 vs 定量"已升级为确定性结论**：001 从综述角度指出 scFM 强在排序弱在定量；003（State，Cell 正刊）用实测证实——最佳成绩 **斯皮尔曼 0.9 是纯排序指标**，而在 MAE 上虚拟细胞挑战赛 2025 **几乎所有参赛模型仍输给"预测平均细胞"的朴素基线**。**一份综述批判 + 一份旗舰实证，独立印证，可直接当作前提使用。**
8. **导师的分享顺序本身是一条阅读路径**：`State（具体标杆）→ 综述（全景与批判）→ MetaRSI（方法论）`。**从具体 → 全景 → 方法论**，不是三条随机资讯。（见情报 003 §8.1）
9. **评估体系而非模型架构，才是这个领域真正的瓶颈**：三条来源完全不同的情报（生物综述 / Cell 论文 / AI 架构报告）殊途同归指向同一处——001 说扰动预测无统一基准，003 的 Cell-Eval 由自家团队提出且 VCC 才刚提供第三方基准，002 的定律一把"可验证性"直接定为闭环存在的前提。**这是本知识库目前最值得押注的判断。**
10. **"细胞集合 > 单个细胞"是 001 的四条 tokenization 路线都没覆盖的维度**：003 的 ST 模型靠"一次看一组细胞"来分离批次噪声与扰动信号，并用最优传输给出理论依据。可迁移到 GRN 推断等同样面临"噪声 vs 信号"分离的任务。
11. ⭐⭐⭐ **【四条情报的终极交汇】真正的资产是数据，不是模型。** 001 说观察数据学不出因果、扰动数据才是锚点；002 的定律五说没有任何循环能创造能力；003 的突破来自 1 亿+扰动细胞而非更大模型；004 说 AI 时代最稀缺的资产不是模型而是闭环人体数据，Moderna/BioNTech 的数据壁垒"几乎无法跨越"。**四种完全不同的语言（计算生物学综述 / AI 形式化定律 / Cell 实证 / 产业观察），收敛到同一条判断——在 AI for Life Science 方向上，护城河建在数据侧，不在模型侧。这可以作为研究规划的前提。**
12. **004 的 AI 数据闭环 = 002 Loop Kernel 与 001 Lab-in-the-Loop 的工业落地形态**：`Design—Build—Test—Learn` 与 Loop Kernel 的 `信号→提议→验证→回流` 同构；而 002 定律一"循环只在可机器验证处闭合"在这里有了具体代价——**验证（QC 放行 + 临床）就是整条闭环最贵最慢的一环**，正是 ARPA-H 砸 1.25 亿美元要攻的那一环。**把"验证器"当作研究对象而非既定条件，现已有四条情报支撑。**
13. **概念同构：004 的「平台知识复用」≈ 导师的「知识联邦」**。前者问"上一款药的知识有多少能服务下一款药"，后者问"各方不共享原始数据时知识如何被提炼共享"——**同一个思想，一个在制药工业层，一个在数据治理层**。这可能正是导师转发该文的原因（见情报 004 §7.3）。
14. **导师关注面覆盖"计算方法 ←→ 产业落地"两端**：001/002/003 是 AI 与计算方法，004 是产业与转化，005 是产业竞争格局。这印证了导师档案 §6.2 的判断——**向他汇报时，"这个工作最终怎么落地"的答案可能和方法创新本身同等重要。**
